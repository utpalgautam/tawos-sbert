# SBERT + CNN for Automated Story Point Estimation

A machine learning project that investigates whether semantic representations generated by **Sentence-BERT (SBERT)**, combined with a shared Convolutional Neural Network (CNN), can predict software issue story points from issue text.

The project evaluates a shared model across eight assigned software projects and compares its predictions against global-median and project-median baselines.

> **Current result:** The implementation, training pipeline, held-out evaluation, and automated reporting are complete. In the current experiment, the CNN achieves a test MAE of **6.4600**, compared with **6.4403** for the project-median baseline. The CNN improves median absolute error, but does not outperform the project-median baseline on overall MAE or RMSE.

## 1. Project Overview

Software effort estimation is an important activity in agile software development. Story points are commonly used to express the relative effort, complexity, and uncertainty associated with completing a software issue.

Manual estimation can be subjective and time-consuming. Machine learning offers a way to investigate whether information in issue titles and descriptions can help estimate story points.

This project implements a pipeline that:

1. Loads and prepares labeled software issues.
2. Generates semantic embeddings using a pretrained SBERT model.
3. Uses a shared CNN to learn patterns in the embeddings.
4. Incorporates project identity through a learned project-ID embedding.
5. Evaluates the model through five-fold cross-validation.
6. Tests the final model on a held-out test set.
7. Compares predictions against simple median baselines.
8. Generates overall and project-specific evaluation reports and visualizations.

The experiment focuses on **within-project evaluation using a shared model across the assigned projects**, rather than training an entirely separate CNN for each project.

## 2. Objectives

The main objectives are:

- Transform software issue text into semantic vector representations.
- Investigate CNN-based regression over SBERT embeddings.
- Incorporate project identity into a shared neural network.
- Use cross-validation for model evaluation and training-duration selection.
- Keep the final test set separate from model selection.
- Compare neural predictions with simple statistical baselines.
- Evaluate both aggregate performance and individual project performance.
- Generate reproducible metrics, predictions, logs, and graphs.

### 3.1 Data preparation

The pipeline uses labeled software issues and their text representations.

The experiment configuration specifies:

- Project identifier.
- Issue key.
- Issue title.
- Issue description.
- Story-point target.
- Issue keys to exclude.
- Policy for handling fractional targets.

The current configuration uses the `ceil` policy for fractional story-point targets.

The resulting labeled dataset contains **22,272 issues**.

### 3.2 Semantic embedding generation

The project uses the pretrained model:

`sentence-transformers/all-MiniLM-L6-v2`

The encoder maps issue text into a 384-dimensional vector.

These embeddings are precomputed and reused during CNN training. The encoder is frozen in the current experiment; it is not fine-tuned as part of the CNN training procedure.

Benefits of precomputing the embeddings include:

- Avoiding repeated text encoding during CNN training.
- Reducing training overhead.
- Keeping the semantic representation fixed across experiments that reuse the same embeddings.
- Separating text representation from regression-model training.

### 3.3 Data splitting

The dataset is divided into development and held-out test sets:

| Split | Number of issues | Approximate proportion |
|---|---:|---:|
| Development | 17,825 | 80% |
| Held-out test | 4,447 | 20% |
| **Total** | **22,272** | **100%** |

Five-fold cross-validation is performed on the development data.

The configured split strategy is random, and duplicate input text is grouped within projects for the cross-validation process. The test set is reserved for final evaluation rather than model selection.

### 3.4 Cross-validation and early stopping

The training pipeline uses five outer cross-validation folds.

Within each outer training fold, a group-based validation split is used for early stopping. The best validation epoch is recorded, and the corresponding outer validation fold is evaluated separately.

The median of the selected best-epoch counts is used to determine the final training duration.

For the completed run, the selected epoch counts were:

```text
Fold 0: 100
Fold 1: 20
Fold 2: 10
Fold 3: 12
Fold 4: 16
```

The median is **16 epochs**. The final model is then trained on the complete development set for 16 epochs and evaluated on the held-out test set.

The held-out test set is not used for selecting the final epoch count.

## 4. Model Architecture

The main model consists of a shared three-layer CNN and a learned embedding representing the project ID.

### 4.1 Input

Each issue is represented by:

- A 384-dimensional SBERT embedding.
- A project identifier.

### 4.2 CNN layers

The configured convolutional channel sizes are:

```text
Input embedding
      |
      v
Conv1D: 128 channels
      |
      v
Max Pooling
      |
      v
Conv1D: 64 channels
      |
      v
Max Pooling
      |
      v
Conv1D: 32 channels
      |
      v
Adaptive Average Pooling
```

The model uses a kernel size of 3, padding of 1, and dropout of 0.2.

### 4.3 Project identity

A learned project-ID embedding of dimension 8 is included in the architecture.

This allows the shared model to incorporate project-specific information while learning from issues across all eight projects.

### 4.4 Regression head

The pooled CNN representation is combined with the project embedding and passed to a regression head that produces a single continuous story-point prediction.

### 4.5 Training configuration

## 6. Experimental Setup

The experiment compares the shared CNN against two baseline models.

### 6.1 Global median baseline

The global median baseline predicts the median story-point value calculated from the development data.

### 6.2 Project median baseline

The project median baseline predicts a project's median story-point value, calculated from development data for that project.

The baselines must be calculated without using held-out test labels.

### 6.3 Shared SBERT + CNN

The main model uses frozen SBERT embeddings and the shared CNN architecture described above.

### 6.4 Evaluation metrics

The project uses four regression metrics.

**Mean Absolute Error (MAE)**

Measures the average absolute difference between actual and predicted story points.

Lower values are better.

**Median Absolute Error (MdAE)**

Measures the median of the absolute prediction errors.

Lower values are better. This metric is less sensitive to extreme errors than MAE.

**Root Mean Squared Error (RMSE)**

Penalizes large errors more strongly because the errors are squared before averaging.

Lower values are better.

**Coefficient of Determination (R²)**

Measures performance relative to predicting the mean target value.

A negative R² means the model performs worse under this criterion than the constant mean predictor on the evaluated data.

## 8. Evaluation and Findings

The experiment demonstrates that a shared SBERT + CNN pipeline can be implemented and evaluated across eight software projects.

### Key findings

1. **The complete pipeline executes successfully.** It performs training, cross-validation, final evaluation, checkpoint saving, and automated report generation.
2. **The CNN has a lower median absolute error.** Its test MdAE is 1.6879, compared with 2.0000 for both median baselines.
3. **Overall MAE remains competitive but not best.** The CNN's MAE is 6.4600, while the project median baseline achieves 6.4403.
4. **RMSE does not improve.** The CNN's RMSE is higher than both baseline values.
5. **Project performance varies.** Different projects exhibit different error patterns and target scales.
6. **DM dominates aggregate evaluation.** It accounts for more than 92% of the held-out test examples.
7. **Further model investigation is justified.** Target distributions, outliers, alternative regressors, and model hyperparameters should be investigated before claiming that the neural approach is superior.

### Overall conclusion

The current experiment establishes a working experimental pipeline and provides a reproducible comparison between a neural model and simple statistical baselines.

The findings are mixed: the CNN improves median absolute error but does not outperform the project median baseline on overall MAE or RMSE.

These results should be treated as the outcome of the current configuration rather than evidence that the proposed model is universally superior.

## 15. Limitations and Future Work

The current implementation is complete, but several research questions remain open.

### 15.1 Prediction errors

The CNN does not outperform the project median baseline on overall MAE or RMSE. Further work is required before claiming that the neural approach is superior.

### 15.2 Imbalanced project distribution

DM accounts for most of the test examples. This means aggregate metrics may not reflect performance across all projects equally.

### 15.3 Extreme errors

The difference between MAE and RMSE suggests that large errors may have a substantial influence on the evaluation. An analysis of residuals and target distributions would help explain this behavior.

### 15.4 Target distributions

The story-point distributions may differ considerably between projects. Target analysis and project-specific baselines can help determine whether the model is learning useful semantic patterns.

### 15.5 Potential future experiments

Possible directions include:

- Comparing additional regression algorithms using the same SBERT embeddings.
- Investigating alternative CNN architectures.
- Evaluating regularization and learning-rate settings.
- Investigating the effect of training duration.
- Studying project-specific target distributions and outliers.
- Comparing equal-project-weighted metrics with issue-weighted metrics.
- Evaluating alternative text representations.
- Fine-tuning SBERT as a separate controlled experiment.
- Performing error analysis on the largest prediction mistakes.

All new model-selection experiments should use development data and cross-validation. The held-out test set should remain reserved for final evaluation.
